## Goal

Turn the current chat-only `/coach` into a real **Digital Personal Trainer** experience reserved for Premium members. Three pillars:

1. **Personalized Program** — a structured 4-week training + recovery + nutrition plan generated by AI from the user's goals, equipment, schedule and current fitness markers.
2. **Progress Tracking** — weekly adherence charts, volume/sleep/hydration trendlines, and an "AI Progress Read" that compares plan vs. actual check-ins.
3. **Adaptive Chat** — existing GPT-5 chat, now aware of the user's active program and latest progress snapshot.

Free/non-premium users see a teaser preview that pushes them to `/paywall`. Apex/legacy Elite users without Premium also see the upsell — Premium is the gate (consistent with The Vault).

---

## 1. Database (one migration)

Two new tables, both with strict RLS scoped to `auth.uid() = user_id`.

**`coach_programs`** — one active program per user, history kept.
```
id uuid pk, user_id uuid not null,
status text default 'active'  -- active | archived | superseded
goal text not null              -- e.g. "build muscle", "fat loss", "discipline reset"
experience text not null        -- beginner | intermediate | advanced
days_per_week int, equipment text, constraints text,
weeks int default 4,
plan_json jsonb not null,       -- full structured program (see schema below)
ai_summary text,                -- short paragraph the coach wrote
generated_with text default 'openai/gpt-5',
created_at, updated_at
```

`plan_json` shape (validated client-side, generated via tool-calling):
```ts
{
  weeks: [
    {
      week: 1, theme: "Foundation",
      days: [
        { day: "Mon", focus: "Lower body strength",
          blocks: [{ name: "Back squat", sets: 4, reps: "5", rpe: 7, notes: "" }, ...],
          conditioning?: "...", duration_min: 55 },
        ...7 entries (rest days marked focus:"Rest")
      ],
      nutrition: { protein_g_per_kg: 1.8, daily_kcal_band: "maintenance", notes: "" },
      recovery: { sleep_target_h: 8, mobility_min: 10, breathwork: "5.5 bpm coherent" }
    }, ...4 weeks
  ],
  weekly_check_targets: { workouts: 4, sleep_avg_h: 7.5, hydration_l: 3, perfect_days: 3 }
}
```

**`coach_program_logs`** — lightweight per-day completion log (separate from `daily_checkins`, which keeps generic data).
```
id, user_id, program_id, week int, day_index int (0–6),
completed bool, perceived_rpe int null, notes text null,
logged_at timestamptz default now(),
unique (program_id, week, day_index)
```

Both tables: RLS `select/insert/update where user_id = auth.uid()`. Inserts also require `has_premium(auth.uid())` (RPC already exists per memory).

## 2. Edge functions

**`coach-generate-program`** (new) — POST, JWT-validated.
- Verifies `has_premium(user_id)` server-side; 403 otherwise.
- Body: `{ goal, experience, days_per_week, equipment, constraints, body_focus[] }`.
- Pulls last 30d of `daily_checkins` for context (averages).
- Calls Lovable AI Gateway `openai/gpt-5` with **tool-calling** (`emit_program` function) to force a strict JSON schema matching `plan_json`. No free-form parsing.
- Marks any existing active program `superseded`, inserts new row as `active`, returns the row.

**`coach-progress-read`** (new) — POST, JWT-validated, Premium-gated.
- Aggregates last 7/28d check-ins + program logs vs. `weekly_check_targets`.
- Calls `openai/gpt-5-mini` (fast, cheap) to write a 4–6 sentence "Coach read" with one concrete adjustment for next week. Cached for 6h per user (column `last_progress_read_at` + text on the program row, or simple in-memory keyed cache table — keep it simple: re-run on demand, no cache for v1).

**`ai-coach`** (edit existing) — extend system prompt:
- Inject the active program summary (current week, today's session) and last progress read.
- No behavior change for non-Premium — but add: if `has_premium=false`, append a one-liner "User is on free trial — keep answers tight and mention Premium unlocks the full program."

## 3. Frontend

### New page `src/pages/Coach.tsx` becomes a tabbed shell

Three segmented tabs (uses existing `SegmentedTabs` component):
- **Today** (default) — today's session card + quick-log buttons
- **Program** — full 4-week plan, week-by-week accordion
- **Progress** — charts + AI read
- **Chat** — existing chat UI moved into a tab

Header keeps the gold gradient identity. Premium badge chip next to "W Coach".

### New components (under `src/components/coach/`)

- `ProgramOnboarding.tsx` — first-run wizard (4 swipable steps via framer-motion):
  1. Goal (chips: build muscle / fat loss / endurance / discipline reset / general health)
  2. Experience (3 cards) + days/week slider (2–6)
  3. Equipment (chips: full gym / dumbbells / bodyweight / kettlebell) + body focus toggles
  4. Constraints free text + "Generate my program" CTA
  Loading state shows shimmer + "Coach is designing your 4-week block…"
- `TodaySessionCard.tsx` — pulls today's day from active program; lists blocks; "Mark session done" button → inserts into `coach_program_logs` and toasts +XP via existing daily_checkins flow (no XP duplication — log is separate from XP).
- `ProgramWeekAccordion.tsx` — clean week tabs, day rows with focus/duration, expandable to show blocks.
- `ProgressDashboard.tsx`:
  - 3 stat tiles: workouts hit vs. target, avg sleep, avg hydration (last 7d).
  - One sparkline (use `recharts`, already in stack — verify) for daily XP last 28d.
  - Compliance bar: % of program days completed this week.
  - "Coach's read" panel (markdown) with refresh button → calls `coach-progress-read`.
- `PremiumCoachUpsell.tsx` — gold panel for non-Premium: shows blurred mock program preview + CTA to `/paywall`.

### Coach gate logic

```tsx
const { isPremium, subscriptionLoading } = useAuth();
if (subscriptionLoading) return <PageSkeleton />;
if (!isPremium) return <PremiumCoachUpsell />;
// Then load active program; if none → ProgramOnboarding; else → tabbed shell.
```

Chat tab keeps the current implementation untouched, just lives inside the new shell.

## 5. Out of scope (v1)

- No video demos for exercises (link out via search would lower trust). Just text + form cues.
- No auto-progression of loads — v1 generates a full 4-week block; week 5 prompts user to "Generate next block" (re-runs onboarding with prefilled answers).
- No nutrition tracking — only macro guidance text inside the program.
- No push notifications wired to today's session in v1 (existing daily reminder is enough).
